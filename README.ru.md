# svodka

Telegram-юзербот для ежедневной сводки: читает историю выбранных вами чатов за
заданное окно времени, делает саммари через Claude и публикует дайджест обратно в
Telegram. Запускается как задача по расписанию в GitHub Actions — без серверов и БД.

> 🇬🇧 In English: [README.md](README.md)

## Как это работает (вкратце)

svodka заходит в Telegram **под вами** (юзербот на MTProto, а не бот), потому что
обычный бот не видит историю произвольных чатов. Вы логинитесь один раз,
интерактивно; на выходе — base64-*сессия*, которая кладётся в GitHub-секрет и
переиспользуется каждым запуском по расписанию. За один прогон svodka читает заданные
чаты за последние `window_hours`, делает саммари через Claude (map-reduce при большом
объёме) и публикует дайджест в `target_chat`.

## Развёртывание

### Требования
- Аккаунт Telegram.
- `api_id` и `api_hash` с <https://my.telegram.org> → **API development tools**.
- Ключ Anthropic API с <https://console.anthropic.com>.

### Почему приватный репозиторий
Публичный репозиторий открывает логи Actions и аккаунт, под которым они выполняются.
Создавайте проект из этого template как **приватный** репозиторий.

### Шаги

1. [![Use this template](https://img.shields.io/badge/Use_this_template-2ea44f?style=for-the-badge&logo=github&logoColor=white)](https://github.com/new?template_name=svodka&template_owner=loadkpi) — выберите видимость **Private**, нажмите **Create repository**.
2. Получите `api_id` / `api_hash` на <https://my.telegram.org>.
3. **Залогиньтесь в Telegram** (один раз). Откройте Codespace — это браузерный
   терминал, локальный тулчейн не нужен — сделайте `api_id`/`api_hash` доступными с
   префиксом `SVODKA_` и запустите команду логина. Codespace может несколько минут
   собираться («Building codespace…») прежде чем откроется терминал — это нормально,
   просто подождите.
   ```sh
   export SVODKA_TELEGRAM_API_ID=<api_id>
   export SVODKA_TELEGRAM_API_HASH=<api_hash>
   go run ./api/cmd/login
   ```
   Введите номер телефона, код из Telegram и пароль 2FA, если он у вас есть. При успехе
   сессия сохраняется:
   - Если рядом есть `gh` CLI с правом писать секреты, логин сам положит её в секрет
     `SVODKA_TELEGRAM_SESSION`.
   - Иначе логин напечатает строку сессии с предупреждением. Вставьте её в
     **Settings → Secrets and variables → Actions** как `SVODKA_TELEGRAM_SESSION`
     вручную и очистите терминал.

   Команда логина никогда не логирует телефон, код или пароль и печатает сессию только
   в запасном (ручном) сценарии.
4. **Добавьте ключ Anthropic** как секрет Actions `SVODKA_ANTHROPIC_KEY`
   (Settings → Secrets and variables → Actions). Если хотите ещё и тест-прогон из
   Codespace — экспортируйте его и там.
5. **Отредактируйте `config.yml`** (можно прямо в web-UI): перечислите `source_chats`
   и пока оставьте `target_chat: "me"`. См. раздел «Настройка» ниже.
6. **Проверьте.** Откройте вкладку **Actions**, включите workflows если попросят,
   выберите **Daily digest** → **Run workflow**. При `target_chat: "me"` дайджест
   придёт в ваши **Saved Messages**. Убедитесь, что логи прогона чистые (только
   метрики — без содержимого сообщений и секретов).
7. **Боевой режим.** Поменяйте `target_chat` на группу/канал, куда можете писать. При
   желании поправьте расписание — см. раздел «Расписание».

## Настройка

Не-секретные настройки живут в `config.yml` (правится в web-UI). Секреты сюда не
кладутся. Документированный пример — [`config.example.yml`](config.example.yml).

| Настройка | По умолчанию | Значение |
|---|---|---|
| `source_chats` | — (обязательно) | Чаты для чтения: `@username`, ссылка `t.me/<name>` или числовой id для приватных чатов без юзернейма. |
| `target_chat` | `"me"` | Куда публиковать. `"me"` = ваши Saved Messages (безопасный предпросмотр); `"@group"` = группа/канал (боевой режим). |
| `window_hours` | `24` | На сколько часов назад читать. |
| `output_lang` | `"ru"` | Язык дайджеста (ISO 639-1, напр. `ru`, `en`). |
| `timezone` | `"UTC"` | IANA-таймзона для времени в дайджесте (в примере — `Europe/Belgrade`). |
| `model` | `"claude-sonnet-4-6"` | Id модели Anthropic (дешевле ↔ лучше): `claude-haiku-4-5` (дешевле/быстрее, ок для большинства сводок) · `claude-sonnet-4-6` (баланс) · `claude-opus-4-8` (макс. качество). |
| `max_output_tokens` | `2000` | Бюджет токенов на вывод саммари. |
| `extra_instructions` | `""` | Необязательная свободная инструкция к промпту дайджеста (тон, структура, акценты). Пусто = дефолт; правила формата Telegram остаются в приоритете. |
| `backlinks` | `true` | Добавлять ссылки `t.me/c` на исходные сообщения, чтобы прыгнуть в первоисточник. Только каналы/супергруппы; приватная ссылка откроется **только у участника** этого чата. `false` — отключить. |
| `routes` | — (необязательно) | Несколько дайджестов за прогон: список `{source_chats, target_chat}`. См. [Несколько дайджестов](#несколько-дайджестов-routes) ниже. |

### Несколько дайджестов (`routes`)

По умолчанию svodka строит **один** дайджест из `source_chats` и шлёт его в один
`target_chat`. Чтобы за один прогон отправлять разные чаты в разные target, добавьте
список `routes` — каждый маршрут это свой `source_chats` → `target_chat`:

```yaml
routes:
  - target_chat: "@team_one"
    source_chats: ["@chat_a", "@chat_b"]
  - target_chat: "@team_two"   # пусто или "" -> Saved Messages
    source_chats: ["@chat_c"]
```

Если задан `routes`, верхнеуровневые `source_chats`/`target_chat` игнорируются, а все
остальные настройки (`window_hours`, `output_lang`, `model`, `backlinks`, …) остаются
**глобальными** для всех маршрутов. Не указывайте `routes` для дефолтного поведения с
одним дайджестом. Маршруты независимы: если один упал, остальные всё равно отправятся, а
прогон помечается упавшим.

### Локальные разовые оверрайды (флаги)

Для одного локального прогона любую настройку можно переопределить флагом, не правя
`config.yml` — удобно подгонять промпт/модель и смотреть результат в «Избранном»:

```sh
go run ./api/cmd/svodka \
  --target-chat me --window-hours 2 \
  --model claude-haiku-4-5 \
  --source-chats "@chat_one,@chat_two" \
  --extra-instructions "Не более 5 пунктов."
```

Приоритет — **флаг > `config.yml` > дефолт**, применяются только реально переданные флаги
(непереданный ничего не меняет). У каждой настройки есть kebab-флаг (`--window-hours`,
`--target-chat`, `--output-lang`, `--timezone`, `--model`, `--max-output-tokens`,
`--extra-instructions`, `--backlinks`, `--source-chats`); полный список — `--help`. **Прогон по
расписанию в GitHub Actions использует `config.yml`** — флаги нужны только локально.

## Секреты

Все секреты — это секреты GitHub Actions с префиксом `SVODKA_`. Они никогда не
попадают в `config.yml`, код, логи или вывод.

| Секрет | Откуда | Примечание |
|---|---|---|
| `SVODKA_TELEGRAM_API_ID` | my.telegram.org | целое число |
| `SVODKA_TELEGRAM_API_HASH` | my.telegram.org | держать в тайне |
| `SVODKA_TELEGRAM_SESSION` | создаётся командой `login` | **полный доступ к аккаунту** — никому не передавать |
| `SVODKA_ANTHROPIC_KEY` | console.anthropic.com | ключ Anthropic API |

> **Про имя переменной.** Конфиг-ридер добавляет префикс `SVODKA_` сам, поэтому ошибка
> о пропущенном значении может показать тег без префикса, например
> `required field APIID (env: TELEGRAM_API_ID)`. Реально задавать нужно
> **`SVODKA_TELEGRAM_API_ID`** — с префиксом.

## Расписание

Задача по умолчанию запускается ежедневно в **06:00 UTC**. Чтобы изменить — правьте
строку `cron` в [`.github/workflows/daily.yml`](.github/workflows/daily.yml); для
ручного прогона в любой момент есть **Run workflow**.

- **GitHub cron всегда в UTC.** Вычтите свой UTC-сдвиг, чтобы получить локальное время
  (напр. 08:00 Europe/Belgrade летом = 06:00 UTC).
- Запуски по расписанию — **best-effort**, возможна задержка.
- Scheduled workflow **отключается после 60 дней** без активности репозитория —
  сделайте коммит или включите его заново, чтобы возобновить.
- IP раннеров меняются между прогонами, поэтому Telegram может иногда показывать
  **«новый вход»**; уже авторизованная сессия продолжает работать.

## Обновление из template

Репозиторий, созданный из template, **не связан** с ним, поэтому кнопки «обновить»
в один клик нет — новые версии вы подтягиваете через git-remote. Делайте это в
терминале Codespace (или в любом локальном клоне). Разовая настройка:

```sh
git remote add template https://github.com/loadkpi/svodka.git
```

Затем, когда захотите свежую версию:

```sh
git fetch template
git merge template/main --allow-unrelated-histories   # --allow-unrelated-histories нужен только в первый раз
git push
```

- **Сохраните свой `config.yml`.** Это файл, который вы настроили под себя, поэтому
  merge обычно конфликтует именно в нём — разрешите конфликт, оставив **свои**
  чаты/таргеты и подобрав новые ключи из обновления (`git checkout --ours config.yml`
  целиком оставит вашу версию). **Секреты не затрагиваются** — они в GitHub Secrets,
  а не в репозитории.
- После merge прогоните приёмочный гейт (`make build && make vet && make test`) и
  запустите **Run workflow** с `target_chat: "me"`, чтобы убедиться, что обновление
  работает до следующего запуска по расписанию.
- Если истории сильно разошлись и кроме `config.yml` сохранять нечего, можно вместо
  merge перенести отдельные коммиты (`git log template/main` — посмотреть их, затем
  `git cherry-pick <sha>`).

## Безопасность и приватность
- Сессия — это полный доступ к вашему аккаунту Telegram. Держите репозиторий
  приватным и никогда не коммитьте и не передавайте строку сессии.
- Секреты живут только в GitHub Secrets — не в `config.yml` и не в коде.
- Логгер пишет только метрики и ваш числовой user id, без содержимого сообщений;
  встроенный MTProto-логгер отключён.
